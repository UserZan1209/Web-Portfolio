Dead End

Project Overview

My idea for the project was to create a hybrid between a more classic arcade survival experience with elements of a rouge-like. DeadEnd is going to be a single player project that will have similar game structure to the 'Call of Duty' series, having three game modes that have cross-progression. The hook of the game is it's visual aesthetic being similar to early 3D games that use low detail and liminal space to create an eerie experience.

Genres: FPS, 3D, Retro, Story, Single Player, Arcade, Survival, Zombies, RPG,
Engine: Unity
Team-Size: 1
Duration: Ongoing



Technical Challenges

While this wasn't my first time developing a game with other developers, it was however my first time working with another programmer. We had a solid idea for the scope of the game which made it easier to plan and divide the workload amongst the team to make development more efficient, as the rest of the team we're not familiar with GitHub I developed the project and the artist would send me the assets they created.

The main issue occurred about 3 weeks before the deadline, after the second programmer hadn't done much of anything he decided to drop out of university as a result his workload was passed onto me. While initially panicked and overwhelmed I soon took a breath and reorganised my workload cutting out extra features in order to submit a functional project.

Moving forward on my own the original project from ended up feeling quite incomplete so after I graduated I went back to the concept to build a new prototype for a retro horror zombies game from scratch. Some of the major features I built for this project ended up being the modular item / inventory system which allowed for quicker development of gameplay depth allowing for ranged enemies to use everything the player can.

This was the first project I needed to actively optimise as much as a could due to the endless nature of the survival genre so concepts like object pooling and rendering tricks became very useful for this project.

Important & Key mechanics

• Endless waves of enemies all managed via a 'spawn manager'. The manager is able to create permutations of enemies with their movespeed and general behaviour. Included is the ability to add alternate rounds to spice up gameplay facing off against stronger zombies or humans that shoot back.
• Modular Inventory & items a system I had been working on across projects that would allow for quicker prototyping having players and NPC objects to interact in the world in a similar fashion creating dynamic gameplay.
• Enemy AI & Behaviour States were the other major component that made this project engaging I took Inspiration from the 'Left 4 Dead' franchise, agreeing that zombies like us as humans would exhibit unique maybe sometimes pointless behaviour. Moving foward with this project I would like to build a sort of system of behaviour evolution in-which while engaging enemies their behaviour can adapt at runtime.
